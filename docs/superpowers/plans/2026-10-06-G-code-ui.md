# G2. Code: AI-first tasks, UI

Spec: `docs/superpowers/specs/2026-10-06-ai-bar-redesign-design.md`, section G.
Backend + IPC: `2026-10-06-G1-tasks-backend.md`. This is the QML side: the
task board in the Code space, task composer, detail/review/plan screens,
notch activity, notification focus, settings and keyboard.

## Data flow

```
backend svc/tasks --tasks.list/updated/removed--> TasksService.tasks (array, newest first)
                  --tasks.activity--------------> TasksService.activity -> TasksActivity (notch)
                  --tasks.open {id, run}--------> TasksService.focusTask(id) -> AI bar Code, task selected
TasksService.tasks + project dir -> TaskModel.board() -> sections / columns -> TaskCard
selected task -> TaskDetail: run.sessionId -> TranscriptView (agents timeline, permissions inline)
                             tasks.diff -> ChangesPane; run.checks -> ChecksView; tasks.debug -> DebugView
Config ai.tasks.* --> tasks.configure {maxParallel, fallbackAgent, notify, mute, mergeMode}
```

## As built / decisions

- **Code space modes**: with no interactive agent session open, Code shows
  the task workspace and the composer creates tasks. The chat icon in
  `TaskOptions` switches back to the interactive agent chat (`CodeEmpty` +
  `Ai.send`), the board icon returns; opening an old session from the
  history still shows its transcript. The docked history column is hidden
  in task mode (the board needs the width; the history button still opens
  the drawer), and task sessions are filtered out of the history
  (`TasksService.sessionIds`).
- **Layout**: compact = sectioned list, the open task replaces it (back /
  Esc); wide ≥ 880 px = columns (or list with `ai.tasks.boardLayout:
  list`), and list + detail side by side once a task is open. Sections are
  ordered attention first: Waiting for you, Running, Review, Queued (also
  usage-limit parking), Done (folded, newest `doneLimit`).
- **Keyboard** works when the board has focus (click it, or Esc in an empty
  composer): N, J/K/arrows, Enter, A (accept: opens Review, confirm strip
  when `confirmAccept`), R (focus the request-changes field), D (discard,
  confirm when `confirmDiscard`), Esc (close the task, then the bar).
  Ctrl+Enter now always submits in every composer (Enter still follows
  `ai.behavior.enterToSend`).
- **Templates**: `tasks.templates.list` for the project feeds the
  Composer's new `extraCommands` (`/review …`), the ⚡ menu and the empty
  board chips; `TaskModel.parseSlash` turns `/id rest` into `{template,
  vars.input}`. Text attachments become `<context>` blocks (and template
  vars `selection`/`clipboard`/`file`), images are referenced by path.
- **Model/effort** of a task come from the agent's catalog
  (`Ai.agents.settingsFor(agent, project)`); shown only for one agent
  (best-of-N runs keep each agent's default).
- **Commit** in the project bar: `git add -A && git commit -m` through a
  static `sh -c` script with argv; "Write with AI" sends `git status
  --short` + `git diff HEAD` (48 KiB) to `Ai.runPrompt` (the quick model).
- **Instructions**: missing AGENTS.md/CLAUDE.md -> "Create with agent"
  starts a task with the new bundled template `instructions`
  (`assets/ai/task-templates/instructions.md`), reviewed like any task.
- **Backend additions**: `tasks.Settings.mute` (event kinds without a
  notification: permission, plan, review, failed, limit) and
  `tasks.Settings.mergeMode` (default for projects without one); pushed by
  `TasksService` from `ai.tasks.*` (`TaskModel.configureParams`).
- **Notification "Open"** needed no new IPC: `tasks.open` already emits
  the `tasks.open` event (handled by `TasksService.focusTask`) and runs
  `ai-code`.
- Live check: `YOZ_LIVE_AGENT=claude go test ./pkg/svc/tasks -run
  TestLiveAgent -v` (skipped by default) ran one real Claude Code task in a
  temp repo: worktree -> agent -> check pass -> review -> accept commit
  (≈7 s).

## Notes for later sub-projects

- `TasksService` (singleton, `modules/services`): `tasks`, `activity`,
  `settings`, `selected`/`selectedId`/`selectedRun`, `select(id, run)`,
  `focusTask(id, run)` (opens the AI bar on it), `create/updatePlan/
  runPlan/followup/accept/discard/cancel/remove/diff/debug`, project
  caches `projects`/`gits`/`templates` + `refreshAll(dir)`, signal
  `focusRequested`. Pure helpers in `modules/services/tasks/TaskModel.js`.
- E (automation/MCP): creating a task from QML = `TasksService.create(
  TaskModel.createParams({...}))`; routines can call `tasks.create`
  directly, the board picks it up from `tasks.updated`.
- D (usage): `ComposerStatus` is hidden in task mode (`TaskOptions` takes
  its place); task cost is `task.cost` (`TaskModel.cost`).
- `TranscriptView.persistKey` keeps a separate scroll memory for views
  that are not the open conversation (task runs).
- `ChangesPane.closable`; `Composer.extraCommands`, `builtinCommands`,
  `insert(text)`.
- Tests: `tests/lib/aiscene.py` BackendService stub now records
  subscriptions (`emit(kind, data)`) and answers `{__error: text}` as an
  IPC error; the scene registers the real `TasksService`.

## Manual test

1. `make build`, restart the shell yourself. Open the AI bar, Code
   (Ctrl+2), pick a scratch git repo in the project menu: the project bar
   shows `branch ↑n ●n`, the instructions chip and the sliders button.
2. Sliders: the check command shows the detected suggestion; set
   `test -f hello.txt`, attempts 2.
3. Type "Create hello.txt with hi" and Ctrl+Enter: the task appears under
   Running (spinner, agent icon, `yoz/<id>` badge, elapsed); the notch shows
   the agent with a spinner. When done it moves to Review and opens:
   summary, check passed, commit message, changes per file.
4. Edit the message, Accept -> confirm -> `git log -1` shows one commit;
   the card moves to Done (folded).
5. Select Codex as well (best of 2) + Plan first: a plan appears under
   "Waiting for you" (`◉ Claude Code is waiting` in the notch). Edit /
   reorder / add steps, Run; review shows both runs side by side, pick one.
6. Ask for something that needs `git push`: the card is highlighted, the
   detail shows the banner and the permission card in the transcript; the
   notification's Allow/Deny/Open work, Open focuses the task.
7. Wide (Ctrl+W): columns; open a task: list + detail. Click the board,
   then J/K, Enter, R (type, Enter), D (confirm), Esc.
8. `/` in the composer lists templates (`/review`, `/tests`, ...); the ⚡
   button too. Debug tab shows argv, stderr and raw events; Checks shows
   attempts and output.
9. Project bar: ● n → Commit popover, "Write with AI", Commit. No AGENTS.md
   -> click the chip -> "Create with agent".
10. Settings -> AI -> Code tasks: default agents, plan first, current
    branch, parallel tasks, fallback agent, merge mode, review options,
    notifications per event, board layout, card details. Settings -> Bar
    activities: "Coding tasks" toggle.
